# Архитектура проекта

Платформа переведена на микросервисную архитектурную модель для обеспечения гибкости и устойчивости.

## Компоненты

### 1. API Gateway
- **Роль**: Единая точка входа.
- **Технологии**: Go, Reverse Proxy.
- **Функции**:
  - Маршрутизация запросов к микросервисам.
  - Раздача статики фронтенда (React).
  - Упрощение CORS-политики.

### 2. Auth Service
- **Роль**: Управление пользователями.
- **База данных**: `db_auth.json`.
- **Функции**: Регистрация, авторизация, выпуск JWT токенов.

### 3. Tasks Service
- **Роль**: Бизнес-логика задач.
- **База данных**: `db_tasks.json`.
- **Функции**: Создание, просмотр и фильтрация задач социального партнерства.

### 4. AI Service
- **Роль**: Интеллектуальный слой.
- **Функции**:
  - Оптимизация описаний задач.
  - Генерация предложений (автоматизация из GitHub PLSP).
  - Чат-ассистент.

## Как они общаются
В данной MVP-версии используется HTTP-взаимодействие через Gateway. Gateway принимает запрос, определяет его тип (например, `/api/tasks`) и перенаправляет на соответствующий порт внутреннего сервиса.

## Гибкость и расширяемость

### Как заменить AI сервис на свой
AI сервис — самый независимый компонент. 
1. Создайте свою реализацию на любом языке (Python, Node, Rust).
2. Запустите её на порту `3003`.
3. В Gateway (файл `services/gateway/main.go`) ничего менять не нужно, если вы сохраните путь `/ai/ask`.
4. Если вы хотите использовать стороннюю модель по API (например, OpenAI), просто измените `AI_BASE_URL` и `AI_MODEL` в файле `.env`.

### Использование локальных моделей
Благодаря микросервису AI, вы можете подключить локальную Llama через Ollama. Просто укажите `http://localhost:11434/v1` в качестве базового адреса. Весь остальной код платформы продолжит работать без изменений.
